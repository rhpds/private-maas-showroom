== Setting up a cloud integrated developer environment (IDE) with OpenShift Dev Spaces

OpenShift Dev Spaces delivers instant access to pre-configured, containerized workspaces running on your OpenShift cluster. It ensures consistency across your team, eliminates "works on my machine" problems, and keeps your development environment in sync with your deployment target.

**Why use Dev Spaces for this workshop?** While you can expose model endpoints externally and develop locally, Dev Spaces offers advantages: your code runs in the same environment where it will deploy, dependencies are pre-configured, and you can access cluster-internal services directly.

NOTE: OpenShift Dev Spaces is included with a full OpenShift Container Platform subscription.

== Meet Your AI Code Assistant

**VS Code Chat** is the agentic harness experience integrated into VS Code, and available in OpenShift Dev Spaces. It provides an interactive chat interface where you can have natural conversations about your code. You can ask the chat to perform actions like:

“Add logging to this function”

“Generate a unit test for this file”

“Refactor this into smaller components”

“Explain what this code does”

The chat will execute these requests directly in your editor, with full awareness of your codebase and project context.

VS Code Chat supports custom model endpoints, making it easy to connect to your private enterprise models.

NOTE: VS Code Chat is an example of an AI-powered coding assistant for this workshop experience. You can easily imagine how this could work with any other desired code assistants that allow you to customize the model used.

== Connect VS Code Chat to Your MaaS Model

In order to connect our model to VS Code Chat we must provide the editor our model's endpoint URL and API key from our MaaS deployment from the previous module. The endpoint we have templated for you, but your key will need to be in your clipboard.

NOTE: If you didn't document your model access information, go back to the OpenShift AI dashboard to the **API keys** section to generate a new token: https://rh-ai.{openshift_cluster_ingress_domain}/

Open the Command Palette in VS Code (`Ctrl+Shift+P` on Linux or `Cmd+Shift+P` on Mac) and run `Chat: Manage Language Models`, then click **+ Add Models → Custom Endpoint**.

Give the group a name (e.g. `MaaS`), paste your API key when prompted, and select **Chat Completions API** as the API type.

VS Code opens a `chatLanguageModels.json` file. Add your model(s) to it:

[source,json,role="execute"]
----
      {
        "id": "publishers/llm/models/nemotron-3-nano-30b-a3b",
        "name": "Nemotron 3 Nano 30B A3B",
        "url": "https://maas.{openshift_cluster_ingress_domain}/v1",
        "toolCalling": true,
        "vision": false,
        "maxInputTokens": 131072,
        "maxOutputTokens": 16384
      }
----

IMPORTANT: The API key entered on the form is saved in a different way, and a randomly generated reference to it is placed above the JSON snippet shown above. Do not change that reference. If you already did, you can go back to the `Chat: Manage Language Models` page and right click on Nemotron to select `Update API Key`.

* **vendor** must stay `customendpoint`. Rename anything else, but touching vendor makes the model silently never appear in the picker.
* **id** must exactly match your model's ID, case-sensitive, including the namespace prefix (here, we've pre-populated it with the model from the cluster).
* **url** is the base URL ending in `/v1` — do NOT append `/chat/completions`.
* **toolCalling**/**vision** must match what the model actually supports, or agent mode misbehaves. Our model supports tools, but not vision, in this deployment.

The file saves automatically, but you can press `Ctrl+S` or `Cmd+S` to be sure.

With the model properly configured, you will be able to chat with the model in the right pane.

Go ahead - test it out with the following prompt:

[source,sh,role="execute"]
----
Explain the software company Red Hat in a short paragraph.
----
