= Usage Analytics and Reporting

In this module, you're stepping into the role of a technical decision maker or platform stakeholder - someone responsible not just for building AI services, but for understanding and reporting on their business impact.

You've deployed, exposed, and consumed a model. Now it's time to ask:

* How is it being used?
* Who's using it the most?
* What's the cost and what's the return?

Let's walk through how to leverage OpenShift AI's built-in dashboards and observability stack to answer those questions.

== Why This Matters

As AI adoption grows, visibility is critical. Organizations need to track:

* Model/API usage by team or model
* Key metrics on model health and performance
* Cost-to-value
* Infrastructure impact (e.g. GPU usage)

This insight enables:

* Cost attribution (per team, per model, per environment)
* Capacity planning (predict future infrastructure scaling needs)
* Understanding ROI for AI workloads

=== Understanding the Dashboard Metrics

**Total tokens**

This represents the total token count (both input and output tokens combined) for all authorized requests through MaaS.

**Total requests**

The number of individual requests made to the model, including each through through an agentic process such as handling tool call results, responding to user feedback, etc.

**Total rate limited**

The number of requests that were denied due to reaching the rate limit for that user on that subscription (you will probably not see many of these on our "Premium" subscription)

**Success rate**

The ratio of the inverse of the above over the total requests

**Active users**

The number of OpenShift AI users who have made any kind of request to the model over the time period selected (should be about the size of your workshop attendance!)

**Token consumption chart**

A rolling average window over token consumption, showcasing peaks and periods of relative high demand easily.

**Token consumption table**

A detailed breakdown per user, subscription, and model of token counts, total requests, and rate-limited requests.

== See Real-Time Usage Tracking (Optional)

Want to see these metrics update in real time? Try this:

1. Keep the dashboard open in one browser tab
2. In another tab, open either:
   * **Gen AI Studio Playground**: Navigate to Gen AI studio → Playground (ensure you are in the right project) (see Module 5)
   * **Dev Spaces IDE**: {devspaces_url} (see Module 3)
3. Send a few messages to the model
4. Filter by your username, and set the time window to something narrow like "Last 5 minutes"
5. Refresh the dashboard data with the dedicated refresh button and you should see your request within 15-30 seconds

NOTE: The delay between the request and it showing up on the dashboard is the scrape interval for collecting and viewing metrics. MaaS rate limits don't depend on this scrape interval, and only visibility into consumption is trailing by this small amount.

== Making Data-Driven Decisions

These dashboards enables critical business and operational decisions:

**Capacity Planning**: If token usage doubles month-over-month, you need proportional GPU scaling. Identifying growth trends early prevents performance degradation and justifies infrastructure investment.

**Cost Attribution**: Mapping consumption metrics per user and subscription enables building a showback and/or chargeback reporting chain based on how your organization consumes models. If one team consumes 80% of tokens on their subscription, that data justifies dedicated capacity allocation and budget decisions.

**ROI Demonstration**: Correlate token usage with business outcomes. High adoption rates combined with faster development cycles (from earlier modules) prove clear return on investment. Measuring AI implementations effect on business outcomes needs at least this level of visibility.

**Optimization**: Hourly usage spikes might indicate batch processing, inefficient prompting, or peak adoption periods. This insight drives optimization strategies and resource scheduling.
